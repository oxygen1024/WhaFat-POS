## 第一版使用流程

1. 搜尋商品名稱、規格或現有 SKU，按品牌／分類篩選。
2. 開啟商品，選擇實際規格，顯示該規格價錢及圖片。
3. 加入購物車、調整數量，選固定金額或百分比折扣。
4. 選擇付款記錄類別；現金輸入收到金額後計算找續。其他付款方式只記錄已在外部完成的付款，並不收取款項。
5. 建立明確標示為試用的本機記錄，查看歷史、列印單據或匯出備份。

使用網頁 App，iPad 可經 Safari 加到主畫面。介面提供橫向及直向排版。首次載入需連線；瀏覽器允許時會快取程式與商品快照，最多保留 80 張看過的圖片。未看過的圖片仍可能需要網絡。iPad 真機、實體收據機、八達通／信用卡機均未實測。

## 正式門市使用所需的下一階段

| 工作 | 原因 |
|---|---|
| 商戶授權的 Shopify 連接及定時更新 | 公開快照不會自行跟隨價格與上下架變更 |
| 伺服器訂單儲存與備份 | 清除瀏覽器資料、裝置損壞或換機會影響本機記錄 |
| 門市庫存、銷售與退款一致性 | 網站可購買不等於門市有現貨；多部 iPad 必須共用可靠資料 |
| 員工權限、折扣與退款審計 | 正式營運需要責任與異動紀錄 |
| 現場測試支付終端、收據機及條碼 | 本版只記錄付款方式，瀏覽器列印不等於設備已整合 |
| 確認 $0、$11,111、缺圖與型號 | 避免將資料缺口直接帶到真實收銀 |

若你管理這個 Shopify 商店，而主要需要標準收銀及庫存同步，Shopify 自家的 POS 亦值得比較：官方說明其能同步訂單與庫存。自訂版適合需要特別的操作流程或畫面，但同步與設備整合需要另外實作。[Shopify 官方說明](https://help.shopify.com/en/manual/sell-in-person)

## 更新目錄

本機工具 `scripts/import_catalog.py` 會依序讀取公開端點，保存來源 SHA-256，再原子更新 `dist/data/catalog.json`。每次正式更新應先檢視價格異常及數量差異，再發布新版。工具不寫入原網站的訂單或庫存。原始來源快照只保留在本機 `data/source/`，不加入網站部署。

加入主畫面步驟依據：[Apple iPad 使用手冊](https://support.apple.com/en-sg/guide/ipad/ipad8f1f7a29/ipados)。
